# Vault guide

This repo is both a Python project and an Obsidian vault. **Code is the source of truth**: retrieval logic, the eval harness, tests and utilities all live in `rag/`, `examples/`, `app/` and `tests/`. The vault only holds Markdown under `notes/` that explains the code and links to it. Measured numbers in notes are always **generated by code** and never typed by hand.

## Opening it

1. Obsidian → *Open folder as vault* → select the repo root (`GraphRAG_playground/`).
2. Trust the vault when prompted. The committed `.obsidian/` config already:
   - shows non-Markdown files (*Files & links → Detect all file extensions*), so `.py` files appear in the explorer and links to them work. Obsidian can't render `.py` files itself and opens them in your default app.
   - hides `venv/`, caches and index artifacts from search, the graph and quick switcher.
   - points the core **Templates** plugin at `notes/00-index/Templates`.
   - colors the graph by variant family.
   - enables the CSS snippet `.obsidian/snippets/rag-vault.css` (Settings → Appearance → CSS snippets), which caps Mermaid diagrams at a readable size and shows the light or dark version of each figure to match your theme. If you had the vault open when the snippet was added, toggle it once or reload Obsidian.
3. Optional community plugins (Settings → Community plugins → Browse):
   - **Dataview**, which renders the live tables in [[RAG map]] and the *Results* section of implemented variants. Without it those blocks show as code; [[Leaderboard]] is plain Markdown and always works.
   - **Templater**, only if you prefer it to core Templates.
   - **obsidian-git**, **Excalidraw** are optional extras.

## Layout

```
notes/
├── 00-index/          RAG map (start here), Glossary, Leaderboard (generated), this guide, Templates/
├── assets/figures/    generated SVG figures (do not edit; see rag/viz/figures.py)
├── variants/<family>/ one note per variant: baseline, retrieval-quality, index, control-flow,
│                      modality, architecture, alternative, cross-cutting
└── results/<variant>/ one generated note per benchmark run (do not edit)
```

## Workflows

**Run the benchmark** (costs API credits; LLM judge included):

```bash
python examples/06_benchmark.py                 # all variants + judge, then exports notes
python examples/06_benchmark.py --no-judge      # cheaper
python -m rag.eval.obsidian_export output/runs/<run_id>.json   # re-export an old run
```

This writes `output/benchmark_results.json` (read by the Streamlit app), archives it to `output/runs/`, writes `notes/results/<variant>/<Variant> <run_id>.md`, and rebuilds [[Leaderboard]].

**Run the tests** (offline, no API calls):

```bash
python -m pytest
```

`tests/test_vault.py` checks every note: valid frontmatter, allowed property values, wikilinks that resolve, relative links (including code links) that exist, and Dataview queries that only use real fields.

**Regenerate figures** (offline; light and dark versions of each):

```bash
python -m rag.viz.figures      # writes notes/assets/figures/*.svg
```

Figures are drawn by code from formulas or real repo data (chunk embeddings, the GraphRAG graph, the vectorless index, the latest benchmark). Notes embed them as `![[name-light.svg]]![[name-dark.svg]]`. The benchmark figure is redrawn automatically by `06_benchmark.py`.

**Diagram conventions:** keep Mermaid diagrams small (a few nodes, short labels, top-down for chains longer than ~4 steps) so they render near 1:1. Obsidian ships Mermaid 11.x.

**Add a variant:**

1. Implement it in `rag/` (with tests in `tests/`).
2. Add a runner to `rag/eval/runners.py` and an entry to `rag/eval/registry.py`.
3. Update its note: set `status: implemented`, list files in `code:`, and add a *Results* Dataview block pointing at `notes/results/<slug>`.

**Write a new note:** use the core Templates command with `Templates/variant`. Keep the filename in Title Case; it must match the wikilinks pointing to it.

## Conventions

- Note filenames in Title Case and match wikilink names; folders in kebab-case.
- Formulas in LaTeX (`$…$`, `$$…$$`), with every symbol defined.
- Diagrams as Mermaid code blocks.
- `status`: `idea` (notes only) → `implemented` (code exists) → `benchmarked` (has result notes).
- Notes never claim measured numbers; those come only from `notes/results/`. Numbers *reported by papers* are attributed to the paper.
